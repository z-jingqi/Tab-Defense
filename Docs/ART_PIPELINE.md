# 怪物与元素特效资源流程

## 目录与交付

- `ArtSource/Monsters/<id>/`：设计图、动作参考、生成工具/素材来源说明。
- `ArtSource/Effects/<id>/`：Blender 源工程、贴图来源、渲染设置说明。
- `Assets/Art/Monsters/<id>/`：整理好的角色 Sprite/图集。
- `Assets/Art/Effects/<id>/`：火焰、闪电、冰晶等透明序列帧/图集。
- `Assets/Data/Animations/`：需要时创建 `Tap Defense > Presentation > Sprite Animation Clip` 资产。

按资源实际产生创建子目录，不放空占位工程。将 `.blend` 放在 Assets 之外，避免 Unity 导入时依赖本地 Blender 版本。导出图、元数据和 `.meta` 一起提交；不要提交缓存、预览视频、渲染临时文件或无关生成记录。大体积源工程接入 Git LFS 前先统一团队方案，不把 LFS 指针误当作可用素材。

## 怪物动画

先确定静态外观、相机角度、轮廓、屏幕尺寸和视觉风格，再制作动作。待机、移动、受击、死亡按用途独立交付，保持画布尺寸、中心点与比例一致。移动动画原地播放，世界位移由战斗逻辑控制，避免动画与逻辑双重位移。

PNG 使用 RGBA，统一 pixels-per-unit、pivot 与帧率。图集按明确的帧序排列，保留边缘 padding，预览深/浅背景下的透明边缘。不要把 AI 单图生成等同于连续动作质量验收。

可选移动动画在 `GameConfig > Enemies` 中配置；未配置时继续使用原有静态 Sprite。动画使用战斗驱动的时间，不使用独立 Update 或全局时间：暂停/升级停止推进，冻结/失衡停止移动动画，重用对象池从首帧开始。正式动画不叠加原型摇摆。

## 元素特效

Blender 制作火焰、爆炸、冰晶破碎的主体动画，输出透明序列帧后整理图集。真实光照、模拟缓存、Blender 材质节点不会直接转换为 Unity 特效。

- 固定形态主体：预渲染序列帧/Flipbook。
- 火星、碎片、烟尘：普通 Particle System，设置明确寿命与数量预算。
- 连接移动目标的雷电：Unity 中的线条/路径几何，跟随实际目标位置。
- 受击闪白、冰冻着色：简单 Sprite 材质/颜色状态，不靠大面积全屏后处理。

视觉表现与元素伤害分开。表现被池上限丢弃也必须正常结算伤害；云层遮蔽仍须隐藏效果、数字和局部音效，不能因新素材泄露隐藏敌人位置。

## 每份资源验收

记录资源 ID、帧数、帧率、是否循环、pivot、pixels-per-unit、预期世界尺寸、透明混合方式及来源/使用权。检查首尾衔接、帧间体积与颜色、静止/慢速/冻结、多个实例叠加和对象池重用。手机性能重点检查图集内存、过度绘制和同时在屏数量；不以单张预览代替 Unity 内的验收。
